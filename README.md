# emsalert — on-call alert → LINE acknowledge

Get a push notification on your phone when the team needs you, answer with one
tap, and the LINE group is told you're coming. Nobody waits for a reply.

```
 trigger (you, a colleague, a shortcut)
        │  POST /notify   or   GET /trigger?token=…
        ▼
 Supabase Edge Function ──────────► Postgres (subscription + call log)
        │  Web Push (VAPID)
        ▼
 Android Chrome → notification with an "I'm on my way" button
        │                                    │
        │ tap the button ────────────────────┼──► LINE group (@751iidqv)
        │ or open the page → big green button ┘
        ▼
 page shows: "You're on the way — posted to the LINE group at 21:04"
```

Everything runs free and always-on: **GitHub Pages** serves the page,
**Supabase** runs the API and the database. Nothing to keep awake, no Render
bill, no cold starts.

## Routes

All under `https://mvagebjizddemohhelta.supabase.co/functions/v1/api`:

| Route | Auth | Purpose |
| --- | --- | --- |
| `GET /health` | — | Is everything configured? |
| `GET /vapid-public-key` | — | The page needs it to subscribe. |
| `POST /subscribe` | `ACCESS_TOKEN` | Register a phone (keyed by endpoint — several devices work). |
| `POST /notify` | `ACCESS_TOKEN` | Raise an alert. `{title, body, source}` |
| `GET /trigger?token=` | `TRIGGER_TOKEN` | Same, as one plain URL for a shortcut. |
| `POST /acknowledge` | `ACCESS_TOKEN` | Post to the LINE group. `{id, message, via}` |
| `GET /state` | `ACCESS_TOKEN` | Latest alert + last 10 calls. |
| `POST /line-webhook` | LINE signature | Records events — this is how you get the group ID. |

Acks are idempotent per alert, so answering from the notification and then
opening the page doesn't post twice. Subscriptions Chrome discards (404/410)
are deleted on the next push.

## Setup

### 1. Database

Supabase dashboard → **SQL Editor** → paste `supabase/schema.sql` → Run.

### 2. Deploy the function

Dashboard → **Edge Functions** → **Deploy a new function** → name it `api` →
paste `supabase/functions/api/index.ts`.

**Turn "Verify JWT" off.** LINE's webhook cannot send a Supabase JWT, so with
it on the webhook silently fails. Every other route is guarded by
`ACCESS_TOKEN` instead.

### 3. Secrets

Dashboard → **Edge Functions → Secrets**. `SUPABASE_URL` and
`SUPABASE_SERVICE_ROLE_KEY` are injected automatically — don't add them.

| Name | Value |
| --- | --- |
| `VAPID_KEYS` | The whole JSON from `vapid-keys.local.json` (generated by `npm run keys`). |
| `VAPID_SUBJECT` | `mailto:your@email` |
| `ACCESS_TOKEN` | Your access phrase. Long and random — it's the only lock on the API. |
| `TRIGGER_TOKEN` | A second, weaker secret for the trigger link. |
| `LINE_CHANNEL_ACCESS_TOKEN` | From the LINE Developers Console. |
| `LINE_CHANNEL_SECRET` | Same place — verifies the webhook signature. |
| `LINE_GROUP_ID` | Empty for now. Step 5 fills it in. |
| `APP_URL` | `https://inwkoki.github.io/emsalert/` |
| `ACK_MESSAGE` | e.g. `🚑 Ponkrit is on the way` |

### 4. The page

Repo → Settings → Pages → Source **Deploy from a branch**, branch `main`,
folder **`/docs`**. It lands at `https://inwkoki.github.io/emsalert/`.

### 5. Getting `LINE_GROUP_ID`

There is no screen anywhere that shows a group's ID. LINE only reveals it by
sending it to a webhook, so the function has to be live first — that's why this
step is last.

1. **OA Manager** (`manager.line.biz`) → Settings → **Account settings** → turn
   on **"Allow joining group chats and multi-person chats"**. Without this you
   cannot invite the bot into the group at all.
2. OA Manager → Settings → **Response settings** → chat mode **Bot**, greeting
   and auto-reply **off** (or the bot answers every message in the group),
   **Webhooks on**.
3. **Developers Console** (`developers.line.biz`) → your channel → **Messaging
   API** tab → **Webhook URL** →
   `https://mvagebjizddemohhelta.supabase.co/functions/v1/api/line-webhook` → **Update**,
   then turn **Use webhook** on. Click **Verify** — it should say Success.
4. On your phone: add **@751iidqv** as a friend, then invite it into the team
   group like any other member.
5. Send any message in that group.
6. Back in Supabase → **SQL Editor**:

   ```sql
   select distinct group_id, source_type, received_at
   from line_webhook_events
   where group_id is not null
   order by received_at desc;
   ```

   That `C…` value is your `LINE_GROUP_ID`. Put it in the secrets (step 3) and
   redeploy isn't needed — secrets are picked up on the next invocation.

7. Test it on its own, before trusting the button:

   ```bash
   curl -X POST https://mvagebjizddemohhelta.supabase.co/functions/v1/api/acknowledge \
     -H "Authorization: Bearer $ACCESS_TOKEN" \
     -H "Content-Type: application/json" \
     -d '{"message":"test from curl"}'
   ```

8. You can turn Use webhook off again afterwards — push messages don't need it.
   Keep the route for the phase-2 chatbot.

The message arrives **as the bot**, not as you — LINE won't let a bot speak in
your name. So write `ACK_MESSAGE` in the third person.

### 6. Your phone (Galaxy S25 Ultra)

1. Open `https://inwkoki.github.io/emsalert/` in **Chrome** (not Samsung
   Internet — its push support is patchier).
2. ⋮ → **Add to Home screen**, and launch it from that icon from now on.
3. Settings → paste the access phrase → **Save & register this device** → allow
   notifications. The pill should read "1 device registered".
4. Settings → **Send a test push to this phone**. Then lock the screen and do it
   again — you should get an **I'm on my way** button on the lock screen.
5. **Samsung will kill this in the background if you skip this:** Settings →
   Apps → Chrome → Battery → **Unrestricted**, and Settings → Battery →
   Background usage limits → turn off **Put unused apps to sleep**.

## Raising an alert

```bash
curl -X POST https://mvagebjizddemohhelta.supabase.co/functions/v1/api/notify \
  -H "Authorization: Bearer $ACCESS_TOKEN" -H "Content-Type: application/json" \
  -d '{"title":"Trauma call","body":"ER, resus 2"}'
```

Or one GET, no headers — good for a phone shortcut or a colleague:

```
https://mvagebjizddemohhelta.supabase.co/functions/v1/api/trigger?token=TRIGGER_TOKEN&title=Trauma%20call
```

Give colleagues `TRIGGER_TOKEN`, never `ACCESS_TOKEN`: it can only raise alerts,
not register devices or post to LINE. It does travel in the URL, so treat it as
a low-value secret and rotate it if the link spreads.

## Local development

```bash
npm run keys      # writes vapid-keys.local.json (gitignored)
npm run dev       # runs the function on :8000 against your Supabase project
```

`npm run dev` needs the same variables in your shell. Without `LINE_*` set,
acknowledging is recorded and the page says LINE isn't configured rather than
failing.
